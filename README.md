# AB Platform — финальный проект Симулятора бигтеха

Учебная A/B-платформа: вы разворачиваете инфраструктуру эксперимента целиком —
сплитовалку, поток событий, оркестрацию расчётов и дашборд — и проводите на ней
полный цикл продуктового A/B-теста: от карточки гипотезы до решения «раскатываем или нет».

Это продолжение [data-platform](https://github.com/simulator-mentoring/data-platform):
там вы освоили рабочее место аналитика, здесь — эксперимент как в Яндексе, Тинькофф или Ozon.

## Что внутри

| Сервис | Зачем | Адрес | Доступ |
|:-------|:------|:------|:-------|
| PostgreSQL | справочники, конфиг экспериментов, абшница | `localhost:5434` | `platform` / `platform` |
| ClickHouse | поток событий `ab.events`, витрины метрик | `localhost:8123` (HTTP) | `default` / `platform` |
| Сплитовалка (FastAPI) | админка экспериментов + API сплитования | http://localhost:8000 (API: /docs) | — |
| Генератор трафика | симулятор пользователей в виртуальном времени | (фоновый сервис) | — |
| Airflow | DAG расчёта метрик эксперимента | http://localhost:8081 | `admin` / `admin` |
| Superset | дашборд эксперимента для продакта | http://localhost:8089 | `admin` / `admin` |

Порты 5434/8081/8089 выбраны так, чтобы не конфликтовать с data-platform.

## Быстрый старт

Нужен Docker Desktop и ~8 ГБ памяти, выделенной докеру (для лёгкого профиля хватит 4).
Клонируй проект в домашнюю папку (не в системные каталоги).

```
make check     # предполётная проверка: докер, память, диск, порты
make up        # лёгкий профиль: базы + сплитовалка + генератор (~3 ГБ)
make up-full   # полный: + Airflow + Superset (~6 ГБ)
```

При первом старте генератор создаёт ~150 тыс. пользователей и наливает 45 виртуальных
дней истории (~7.5 млн событий) — меньше минуты, прогресс в `docker compose logs -f generator`.

Дальше — по шагам финального проекта: **[docs/assignments.md](docs/assignments.md)**.

## Как устроено виртуальное время

Эксперимент, который в жизни идёт две недели, здесь занимает пару часов: время
симуляции ускорено (по умолчанию 1 виртуальный день = 10 реальных минут, параметр
`SIM_ACCEL` в `.env`). Генератор каждый «час» симулирует сессии пользователей:
заходы, просмотр цены, заказы, отмены — с сезонностью по часам и дням недели и
честной гетерогенностью пользователей (небольшая доля ездит непропорционально много).

Ключевое правило: **вся аналитика — только по виртуальному времени** (`event_ts`,
`event_date`, `assigned_at`). Текущий виртуальный момент: `GET /sim/now` у сплитовалки.

## Как устроено сплитование

Пользователь попадает в эксперимент в момент первого захода (exposure), а не заранее:
генератор при каждой сессии спрашивает у сплитовалки вариант для пользователя.
Вариант определяется детерминированным хешированием `murmur3(соль_эксперимента + user_id)`
— один и тот же пользователь всегда получает один и тот же вариант, состояние не нужно.
Назначение фиксируется в абшнице `ab.assignments` (Postgres), откуда Airflow DAG
реплицирует её в ClickHouse для join-ов с событиями.

Эффекты вариантов зашиты в пакет сценария генератора. Файл закодирован —
не декодируй, если не хочешь заспойлерить себе результат эксперимента.

## Структура проекта

```
docker-compose.yml      # весь стек; лимиты памяти на каждом сервисе
splitter/               # FastAPI: эксперименты, сплитование, реестр метрик
generator/              # симулятор трафика: популяция, воронка, виртуальные часы
airflow/dags/           # DAG репликации абшницы и расчёта витрины метрик
superset/               # образ Superset с драйверами ClickHouse/Postgres
postgres/init/          # схемы core (пользователи) и ab (эксперименты)
clickhouse/init/        # ab.events, ab.assignments, витрина метрик
templates/              # карточка эксперимента, ноутбук расчёта выборки
docs/                   # задания, гайд по дашборду, troubleshooting
```

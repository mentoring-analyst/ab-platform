# Гайд ментора

Этот файл — для ведущего курса. Студентам он не нужен (но и не секретен,
кроме раздела про сценарий — там просто спойлеры).

## Ground truth: какие эффекты зашиты

Истинные эффекты вариантов лежат в `generator/config/scenario.yaml.b64` (base64).
Посмотреть: `python3 -c "import base64; print(base64.b64decode(open('generator/config/scenario.yaml.b64').read()).decode())"`

Текущий сценарий `pricing_point_estimate`:
- **A** — контроль, диапазон цены.
- **B** — точечная цена: **+2.0 п.п.** к конверсии в заказ, −0.3 п.п. к отменам.
  Ожидание: значимый рост целевой при полных ~2 неделях теста, guardrail в норме.
- **C** — заниженная точечная цена (×0.93): **+2.8 п.п.** к конверсии, но **+4.0 п.п. к отменам**
  (цена в поездке оказывается выше показанной). Ловушка: студент, который смотрит
  только целевую метрику, порекомендует C. Правильный ответ — B или «C дорабатывать»,
  с явной ссылкой на защитную метрику.

Тем же эффектам подчиняется `pricing_rollout` — код эксперимента для шага
поэтапной раскатки из README: победивший вариант на широкой доле ведёт себя
так же, как в основном тесте.

Правило генератора: вариант, которого нет в сценарии, ведёт себя как контроль.
Поэтому A/A-тесты работают из коробки: любой эксперимент с кодом, которого нет
в сценарии, — честный A/A с нулевым эффектом (в README это шаг 4,
`aa_sanity_check`).

## Как поменять сценарий

1. Напиши YAML (структура: `experiments → <код> → variants → <имя> → параметры`).
   Параметры: `display` (`range` | `point` | `point_low`), `order_uplift_pp`,
   `cancel_delta_pp` — аддитивные процентные пункты.
2. Закодируй: `python3 -c "import base64,sys; print(base64.b64encode(open('scenario.yaml').read().encode()).decode())" > generator/config/scenario.yaml.b64`
3. Пересобери генератор: `docker compose up -d --build generator`.

## Калибровка чисел под учебную легенду

Ключевые параметры в `.env` / `generator/config/simulation.yaml`:
- `POP_PER_REGION=25000` даёт по региону аудиторию ~25 тыс. За 2 виртуальные недели
  эксперимент на одном регионе набирает почти всю активную аудиторию → MDE ≈ 1.5–2 п.п.
  Запрос продакта «MDE 0.5 п.п.» при этом требует на порядок больше выборки —
  ровно та невыполнимая задача из ноутбука расчёта.
- `SIM_ACCEL=144`: 1 виртуальный день = 10 минут; 2 недели теста ≈ 2.3 часа.
  Для демо можно 720 (день = 2 минуты).
- `HISTORY_DAYS=45`: предпериод для базовых конверсий и расчёта выборки.

## Общий сервер для студентов без ноутбука

На сервере с 16 ГБ поднимается **один** общий стек (не стек на студента).
Изоляция: каждому студенту — свой регион в фильтрах аудитории (6 регионов
из коробки), свой эксперимент со своим кодом, личные учётки в Airflow/Superset
(создаются в их UI). Эксперименты в разных регионах не пересекаются по
пользователям и не искажают друг друга.

Если студентов больше шести — добавь регионы в `simulation.yaml` и
`postgres/init/01-init-platform.sql` до первого запуска (или пересоздай стек).

## Что проверять при приёмке работ

1. **Карточка** (приходит в телеграм файлом или Notion-ссылкой): гипотеза
   в формате «Если X, то Y изменится на W», MDE осознан
   (не скопирован 0.5 от продакта), защитные метрики есть, дерево решений ветвится.
2. **Расчёт выборки**: калькулятор и симуляции сходятся; есть внятный ответ продакту
   про 0.5 п.п. (невыполнимо на трафике региона — предложены альтернативы).
3. **Дизайн**: доли групп соответствуют карточке, аудитория — своему региону.
4. **Дашборд**: набор аудитории, SRM, метрики; подписи человеческие.
5. **Анализ**: SRM-проверка сделана ДО метрик; критерии соответствуют типам метрик
   (доля → z-тест, среднее → t-тест/Манн-Уитни, ratio → дельта-метод/бутстрап);
   вывод по C-варианту учитывает guardrail.
6. Сверь найденные студентом эффекты с ground truth сценария.

## Диагностика

- Виртуальные часы: `GET /sim/now` или `SELECT * FROM ab.sim_clock` (Postgres).
- Логи генератора: `docker compose logs -f generator` — раз в виртуальный день
  печатает дату, при ошибках переподключается сам.
- Витрина пустая → включён ли DAG в Airflow, закрыт ли хотя бы один виртуальный
  день после старта эксперимента.
